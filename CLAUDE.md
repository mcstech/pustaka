## Project Overview

PUSTAKA (e-bacaan) is a religious scripture reading application built with Fresh (Deno) that displays Quranic verses and Bible passages. The application is called "Koleksi Ayat-Ayat Suci" (Collection of Holy Verses).

## Tech Stack

- **Framework**: Fresh 2.x (Deno web framework)
- **Runtime**: Deno
- **UI Library**: Preact with signals
- **Styling**: Tailwind CSS 4.x + DaisyUI
- **Build Tool**: Vite
- **External APIs**:
  - QuranJS API for Quranic content
  - helloao.org API for Bible content

## Development Commands

```bash
# Start development server with hot reload
deno task dev

# Run linting and type checking
deno task check

# Build for production
deno task build

# Start production server
deno task start

# Generate searchable documents from Quran data
deno task generate-quran

# Generate searchable documents from Bible data
deno task generate-bible

# Generate both Quran and Bible documents
deno task prepare-docs

# Update Fresh framework
deno task update
```

## Architecture Overview

### Data Flow

1. **Static Data Loading**: Scripture data is stored in `data/` directory:
   - `data/quran/surah/*.ts` - Individual surah modules with verses
   - `data/quran/surahs.json` - Metadata for all surahs
   - `data/bible/ind_ayt/` - Indonesian Bible translation data
   - `data/documents.json` - Generated search index for verses

2. **Middleware Pattern**: The `routes/(firman)/_middleware.ts` calls `prepareFirman()` which loads scripture data into `ctx.state` based on the route:
   - `/quran` routes → loads Quran chapters into `ctx.state.quran`
   - `/alkitab` routes → loads Bible books into `ctx.state.alkitab`

3. **State Management**: The application uses Fresh's built-in state management defined in `utils.ts`:
   - `State.quran` - Contains Quran chapters with verses
   - `State.alkitab` - Contains Bible books with translation data
   - State is populated by middleware and accessed in page components

### Key Architecture Patterns

**Route Grouping**: The `(firman)` route group shares middleware for scripture data loading. Both `/quran` and `/alkitab` routes inherit from this middleware.

**Type System**: Scripture data structures are strictly typed:
- `types/quran/surah.ts` - Defines Quran verse structure with translations and tafsir
- `types/bible/books.ts` - Defines Bible book and chapter structure with complex content types (verses, headings, footnotes, etc.)

**Islands Architecture**: Interactive components use Fresh islands:
- `islands/search-bar.tsx` - Modal search functionality
- `islands/ThemeToggle.tsx` - Theme switching
- Islands are lazily hydrated on the client side

**Search System**: Uses a pre-built search index:
- `libs/doc-find.ts` wraps the search functionality
- Search index is generated by scripts from scripture data
- The actual search library is imported from `output/docfind.js` (WebAssembly/optimized)

### Data Generation Scripts

Two scripts generate the searchable documents index:

1. **`scripts/generate-documents.ts`**: Reads Quran data from `data/quran/surah/*.ts` files, extracts Indonesian translations, and generates search index entries
2. **`scripts/generate-bible-documents.ts`**: Fetches Bible chapters from helloao.org API, extracts verses, and appends to the search index

Both scripts output to `data/documents.json` which powers the search functionality.

### Environment Variables

Required for Quran API access (stored in `.env`):
- `QURAN_CLIENT_ID` - QuranJS API client ID
- `QURAN_CLIENT_SECRET` - QuranJS API client secret
- `QURAN_AUTH_URL` - QuranJS authentication URL
- `QURAN_API_BASE_URL` - QuranJS content API base URL

The Quran client is configured in `libs/quran.ts` with Indonesian as the default language.

## File Structure

- `main.ts` - Application entry point, registers routes and static files
- `routes/` - File-system based routing
  - `(firman)/` - Shared route group for scripture pages
  - `(firman)/quran/` - Quran display routes
  - `(firman)/alkitab/` - Bible display routes
- `components/` - Reusable UI components
- `islands/` - Interactive client-side components
- `libs/` - Utility libraries and API clients
- `data/` - Scripture data and search index
- `types/` - TypeScript type definitions

## Working with Scripture Data

**Quran Verses**: Each surah module exports a default object keyed by surah ID. The structure includes:
- `text`: Arabic verse text (keyed by verse number)
- `translations`: Multi-language translations (e.g., `translations.id.text` for Indonesian)
- `tafsir`: Commentary/explanation by source

**Bible Chapters**: Bible data from helloao.org follows a complex content model:
- Chapters contain arrays of `ChapterContent` which can be: verse, heading, line_break, or hebrew_subtitle
- Verses contain arrays that can include: strings, formatted text, inline headings, or footnote references
- When rendering, check the `type` field to determine content type

## Common Patterns

**Adding a New Scripture Route**:
1. Create route file under `routes/(firman)/`
2. Access scripture data from `ctx.state.quran` or `ctx.state.alkitab`
3. The middleware automatically populates state based on pathname

**Rendering Verses**:
- Quran: Use RTL direction (`dir="rtl"`), apply `font-lpmq` class for Arabic text
- Bible: Check `textDirection` from translation metadata, handle complex content types

**Testing Search**:
1. Ensure `data/documents.json` is generated (run `deno task prepare-docs`)
2. The search modal initializes the search library lazily on first open
3. Search returns objects with: `title`, `category` (quran/bible/wejangan), `href`, `body`, `keywords`
